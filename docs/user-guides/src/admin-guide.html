INTRODUCTION
Who This Guide Is For

This guide is for anyone with administrative responsibility in Silent Whisper: a System Administrator overseeing the whole deployment, an Organization Administrator managing membership across an organization, or a Workspace Owner or Manager running a team's day-to-day workspace. It covers what each of these roles can do, how membership and invitations work, and the trust and audit model underpinning the platform.

For everyday messaging features, see the companion User Guide — this guide focuses strictly on administrative capability.

CORE PRINCIPLE

Silent Whisper separates structural administration from content access. Administering a workspace's membership and settings never, by itself, grants access to the private conversations inside it. This distinction shapes almost every rule in this guide, and is explained fully in Chapter 11.

FOUNDATIONS
Roles & Permissions

Administrative authority in Silent Whisper is layered, and each layer's authority stops at its own boundary: System Admin (global, every organization and workspace) contains Org Admin / Org Member (one organization) contains Owner / Manager / Member (one workspace) contains Channel member (one channel).

ROLESCOPEPRIMARY RESPONSIBILITIES
System AdministratorEntire deploymentCreate organizations; create and manage user accounts; oversee every workspace structurally; configure AI settings; review analytics and the audit log.
Organization AdministratorOne organizationInvite, remove, and change the role of organization members.
Organization MemberOne organizationNo administrative permissions.
Workspace OwnerOne workspace (exactly one Owner at a time)Full control of the workspace: settings, visibility, membership, roles, ownership transfer.
Workspace ManagerOne workspaceManages plain members (invite, roster, password reset, removal); may archive the workspace only if the Owner has granted that specifically.
Workspace MemberOne workspaceOrdinary participant; no administrative permissions.
Channel memberOne channelAny member may rename the channel, add or remove other members of a private channel, or leave.
NOTE

Organization membership has no "last admin" safeguard by design — an organization can end up with zero Org Administrators if the last one is removed or leaves. Keep this in mind when restructuring org-level access.

GLOBAL OVERSIGHT
System Administration

Creating organizations

Only a System Administrator can create a new organization. Its creator becomes that organization's first Organization Administrator.

Creating and managing user accounts

Silent Whisper has no public sign-up — every account is created directly by a System Administrator, or arrives through an invitation (Chapter 7). System Administrators can:

  • Create a new user account.
  • Disable or re-enable an account — disabling takes effect immediately, ending any active session and blocking further sign-in right away, not just once a session naturally expires.
  • Promote or demote System Administrator status for any user.
  • Reset any user's password.
  • See which organizations a given user belongs to.

Cross-workspace oversight

A System Administrator can view every workspace across every organization, and manage a workspace's structure — settings, archiving, visibility, membership and roles, channels, and ownership — even without being a member of it. This is the "structural override" referenced throughout this guide.

IMPORTANT

Using the structural override to manage a workspace does not grant a System Administrator access to its private channels or direct messages, and it does not add them as a member of any channel. To actually read conversation content, a System Administrator must take a further, separate, and audited step — the same one any other outsider would need.

ORGANIZATIONS
Organization Management

Organization Administrators manage who belongs to the organization and what role they hold there:

  • Invite or add members to the organization.
  • Remove members from the organization.
  • Change a member's role between Organization Administrator and Organization Member.
  • Rename the organization.
  • Archive the organization when it's no longer active — archiving blocks new members, invitations, and workspaces from being added underneath it, while keeping it browsable for historical reference. Archiving can be reversed.

Any organization member — administrator or not — can leave the organization on their own at any time, without needing anyone's approval.

WORKSPACES
Workspace Management

Creating a workspace

Any authenticated user may create a workspace for themselves — this is self-service and doesn't require administrator approval. The creator automatically becomes its Owner.

Visibility

A workspace can be discoverable (visible in a browsable list that any user can search and request to join) or kept private (findable only by direct invitation). The Owner can change this at any time.

Membership & roles

Owners and Managers can invite or add members. Owners additionally control promotion and demotion between Manager and plain Member. Only an Owner can promote someone to Manager or remove Manager status.

Delegating archive rights, and transferring ownership

By default, only the Owner can archive or unarchive a workspace; an Owner can delegate that ability to Managers explicitly. Ownership can be transferred to another member — this is the only way an Owner can leave their own workspace, since Silent Whisper requires exactly one Owner at all times.

CHANNELS
Channel Management

Channel management is deliberately lightweight — treated as ordinary participation rather than a special privilege, on the reasoning that anyone trusted enough to be in a channel is trusted enough to help run it:

  • Creating a channel — any workspace member can create a new channel, public or private.
  • Renaming — any current member of a channel can rename it.
  • Adding members to a private channel — any current member can add another workspace member.
  • Removing a member from a channel — removes them from that channel only, without affecting their workspace membership.
  • Leaving — any member can leave a channel at any time, independent of their workspace membership.
NOTE

Public channels are self-joinable by any workspace member — no one needs to add them. Private channels require an existing member to add the person; the channel is invisible to everyone else, including in search and browsing.

PEOPLE
Member Lifecycle & Invitations

Two ways to invite

METHODHOW IT WORKS
Invitation linkA shareable link created by an inviter. Whoever redeems it supplies their own details at that time. The inviter can revoke the link before it's used.
In-app invitationSent to a specific, already-registered user by name. It appears to them as a notification they can Accept or Decline — no link required.

Resetting a member's password

A workspace administrator (Owner or Manager) can reset the password of a member within their workspace; a System Administrator can reset any user's password organization-wide. There is no self-service, email-based password reset — this is by design. Usernames are matched case-insensitively at sign-in, so a casing mismatch is never the reason someone can't log in.

Removing a member

Workspace administrators can remove a member from the workspace; members can also always remove themselves (Chapter 5). Removal from a workspace does not automatically remove someone from their parent organization, and vice versa — each layer is managed independently.

CONFIGURATION
AI Settings

The AI features described in the User Guide (channel summaries, task extraction, workspace digests, semantic search, and per-entity "What we know" summaries) are configured centrally, and only a System Administrator can change that configuration — no workspace-level role can. Configurable settings include:

  • Which AI provider and model are in use.
  • The endpoint the platform connects to for AI processing.
  • Request timeouts and response length limits.
  • Whether responses stream incrementally or arrive all at once.
  • The prompt version in use.
WHY THIS IS CENTRALIZED

AI configuration was tightened to System-Administrator-only after a review found that certain workspace-level roles could otherwise reach settings with broader security implications than intended (including where AI requests are allowed to be sent). Keeping this single-purpose and centrally owned closes that gap.

USAGE & COORDINATION METADATA
Admin Analytics Dashboard

Reachable from the Admin hub as Admin Analytics, this is a System-Administrator-only dashboard of usage and coordination metadata — never message content. It has three tabs:

  • Activity — message and active-user counts bucketed by day or week, scoped to an organization, workspace, or channel, plus a Dormant Channels list of channels with no top-level message in a configurable number of days.
  • Collaboration — a structural membership-overlap graph between users who share more than a configurable number of channels (2, by default), and an interaction-trend chart of reply-based activity between people over time.
  • Sentiment Trends — an approximate, bucketed tone trend derived from the same embeddings already computed for semantic search — never a second AI call, and never the message text itself.
NOTE

Every tab structurally excludes direct messages and group DMs, the same way ordinary analytics reads do. Scoping Sentiment Trends to a single user — the one variant that's individual tone-monitoring rather than a many-person average — is itself an audited action; every other view here is a plain metadata read, unaudited like the rest of this dashboard.

ACCOUNTABILITY
Audit Log & Compliance

Silent Whisper keeps a standing audit log of administrative and security-relevant actions — account creation and changes, role and ownership changes, workspace and organization lifecycle events, authentication events, and access to the audit log itself.

Reviewing the log

System Administrators can browse recent audit events from the administration area, in reverse-chronological order.

Verifying integrity

Each entry in the audit log is cryptographically linked to the one before it, so any attempt to alter or remove a past entry breaks the chain in a detectable way. A one-click Verify Integrity action re-checks the entire chain on demand. The underlying database also enforces that log entries can never be updated, deleted, or bulk-erased — even by the application itself — so the log's append-only guarantee doesn't depend on any one piece of code behaving correctly.

NOTE

Viewing the audit log and running an integrity check are themselves logged — reviewing the log leaves a record of the review.

TRUST MODEL
Security & Privacy Principles

Structural management is not content access

This is the single most important idea in this guide. Being able to administer a workspace's settings, membership, or channel list never by itself grants the ability to read the messages inside its private channels or direct messages. Anyone — including a System Administrator — who wants to read content they aren't already a participant in must take a further, explicit, and audited step to do so. The same boundary applies to entity AI summaries, Knowledge Explorer trending, and the Analytics dashboard: each is scoped to what the viewer could already see, never more.

Private resources are invisible, not just restricted

If you're not a member of a private workspace or channel, Silent Whisper treats it as though it doesn't exist for you, rather than showing it and refusing access.

Account security

  • Disabling an account takes effect immediately — any live connection is closed at once, and re-authentication is blocked, rather than waiting for a session to expire naturally.
  • Session hijacking protection — if a previously used sign-in credential is ever replayed after it should have expired, Silent Whisper treats this as a sign of compromise and signs out every other active session for that user automatically.
  • Password requirements — new passwords must meet a minimum length and are checked against a list of known-compromised passwords.

Rate limiting

Sign-in attempts, message sending, invitation redemption, and AI feature requests are all automatically rate-limited to protect the platform from abuse and overload, with no administrator configuration or monitoring required.

DISCIPLINE
Best Practices Checklist
  • Assign a second Organization Administrator wherever possible — there's no built-in safeguard against an organization ending up with zero.
  • Transfer workspace ownership deliberately, and confirm the new Owner is who you intend before an existing Owner steps away — ownership is unique and consequential.
  • Prefer in-app invitations for people who already have an account, and reserve invitation links for genuinely new people — links can be shared further than intended before they're redeemed.
  • Revoke an invitation link as soon as it's no longer needed.
  • Review the audit log periodically, not only when investigating something specific — a quiet regular habit catches more than a reactive one.
  • Remember that structural oversight of a workspace is not the same as reading its content — don't rely on administrative access as a substitute for actually being a member of a channel you need visibility into.
  • Archive organizations and workspaces that are no longer active rather than leaving them live and unmonitored — archiving is reversible and keeps active membership lists meaningful. The Analytics dashboard's Dormant Channels view (Chapter 9) is a good prompt for when it's time.
